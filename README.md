# AyuGram для iOS

Версия для iPhone. Ветки `main` и `ios` содержат одно и то же; сборка идёт из `ios`.

В Actions выберите **Build AyuGram iOS**. Workflow всегда собирает содержимое ветки `ios`.

Аналог AyuGram на базе открытого [Telegram-iOS](https://github.com/TelegramMessenger/Telegram-iOS) (GPL-2.0).
Функции взяты из разбора Android-сборки `vanilla-AyuGram-lite-20261005.apk`, подробности в
[docs/APK_ANALYSIS.md](docs/APK_ANALYSIS.md).

Репозиторий не содержит кода Telegram: в нём только патчи к тегам Telegram-iOS, по папке на тег
([patches/release-13.1.1](patches/release-13.1.1), [patches/release-13.0.0](patches/release-13.0.0)). GitHub Actions скачивает Telegram-iOS,
накладывает патч и собирает `.ipa`.

## Что умеет

Настройки AyuGram (Настройки → AyuGram) разбиты на пять групп: «Режим призрака», «Сообщения»,
«Интерфейс», «Нейросеть» и «Дополнительно».

**Режим призрака** (Настройки → AyuGram → Режим призрака). Пока он включён, на сервер не уходят:
- отметки о прочтении (`readHistory`, `readDiscussion`, `readMessageContents` и др.);
- просмотры историй (`stories.readStories`, `incrementStoryViews`);
- статус «в сети»;
- «печатает…» и статус загрузки.

Как в AyuGram4A и AyuGram Desktop, при скрытом «в сети» периодический «в сети» уходит как
«не в сети», а при сворачивании «не в сети» уходит всегда. Опция «Автоматический „не в сети“»
следит за вашим статусом: если сервер сам показал вас в сети (например, после отправки сообщения),
сразу уходит «не в сети». Просмотры постов в каналах при скрытых отметках о прочтении не засчитываются.
Чат, прочитанный в режиме призрака, отмечается прочитанным у собеседника, когда вы откроете его с выключенным режимом.

Дополнительно:
- «Читать при действиях»: когда вы отправляете сообщение или реакцию, чат отмечается прочитанным;
- «Отправлять без звука»: никогда, всегда или только в режиме призрака;
- «Предлагать призрака для историй»: если просмотры историй не скрыты, перед открытием историй
  приложение предлагает включить режим призрака на время просмотра; после закрытия он выключается.
  Пока вопрос на экране, история стоит на паузе и просмотр на сервер не уходит; после ответа «Нет»
  просмотр открытой истории отправляется;
- «Статус призрака в списке чатов»: 👻 рядом с заголовком «Чаты».

**Сохранение сообщений:**
- сообщения, удалённые собеседником, остаются в чате с меткой 🗑 и могут быть полупрозрачными;
- при каждой правке сохраняется прежний текст. Меню сообщения → «История правок».
- «Удалённые сообщения»: зажмите аватарку в личном чате, группе или канале. Третий пункт после
  профиля и поиска открывает сохранённые удаления только этого чата. Одноцветная корзина
  подстраивается под тему. Есть автор, время отправки и удаления, фильтр за 24 часа / 7 дней /
  30 дней / всё время (по умолчанию). Нажатие
  открывает сообщение в чате, где фото и файлы открываются как обычно (если успели загрузиться).

Всё хранится локально, в базе Telegram на устройстве.

Сообщение сохраняется, только если приложение успело его получить. Свёрнутое приложение iOS
усыпляет через десятки секунд или несколько минут. Опция «Держать в фоне» (Настройки → AyuGram → Дополнительно)
проигрывает беззвучное аудио, чтобы iOS не усыпляла приложение и соединение не обрывалось.
Батарея расходуется быстрее. Приложение, закрытое смахиванием, не работает в любом случае.

**Автоотправка** (Настройки → AyuGram → Сообщения → «Автоотправка»): в поле ввода перед кнопкой
стикеров появляется ⚡️. В её меню задаются текст, до 10 фото и видео (несколько уходят альбомом,
текст становится подписью) и интервал в секундах; шаблон хранится отдельно для каждого чата.
«Запустить» отправляет его сразу и затем каждый интервал, «Остановить» прекращает. Отправка идёт,
пока приложение открыто; в свёрнутом — только с «Держать в фоне». Выключение настройки
останавливает все запущенные отправки. Частые одинаковые сообщения Telegram может счесть спамом.

**Интерфейс:**
- блокировка рекламы: спонсорские сообщения в каналах, реклама в поиске и закреплённый канал спонсора прокси не загружаются (включена по умолчанию);
- скрытие историй: чужие истории убираются из списка чатов и архива, в профиле их можно открыть;
- отключение округления чисел (1.23K → 1,234) и время сообщений с секундами (12:34 → 12:34:56);
- ID и DC в профиле в формате Telegram API или Bot API; нажатие копирует ID.
- вкладка «Профиль» справа от «Настроек» открывает ваш профиль (включается и выключается в настройках сразу, без перезапуска).

**Нейросеть** (Настройки → AyuGram → Нейросеть, нужен бесплатный ключ Google AI Studio):
в меню сообщения пункт «Нейросеть» → «Пересказать кратко» или «Ответить на вопрос», ответ Gemini
открывается в отдельном окне. Модель выбирается в настройках (Flash-Lite самая быстрая, Flash подробнее);
если она перегружена, отвечает следующая. «Проверить скорость моделей» показывает, какая сейчас свободна. В Google уходит только текст сообщения: имена, @юзернеймы, ссылки t.me,
телефоны, e-mail и длинные числа заменяются заглушками, данные аккаунта и чата не отправляются.
На бесплатном тарифе Google может использовать присланные тексты для обучения моделей.
Из России Gemini доступен только через VPN или SOCKS5-прокси, включённый в Telegram (запрос нейросети идёт через него); MTProto-прокси передаёт только трафик Telegram и не подходит.

## Сборка через GitHub

1. Создайте на GitHub **приватный** репозиторий и загрузите в него эту папку.
2. Получите `api_id` и `api_hash` на https://my.telegram.org → *API development tools*.
3. В репозитории откройте *Settings → Secrets and variables → Actions* и добавьте секреты
   `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.
4. *Actions → Build AyuGram iOS → Run workflow*.
5. Когда сборка закончится, скачайте `AyuGram-iOS-*.ipa` из раздела *Artifacts* этого запуска.

Первая сборка идёт долго, 1,5–3 часа. Повторные быстрее благодаря кэшу Bazel.

### Если сборка падает на версии Xcode

Каждый тег Telegram-iOS требует свой Xcode (`versions.json`). Workflow выбирает самый новый Xcode
на раннере и передаёт `--overrideXcodeVersion`.
- `release-13.1.1` (по умолчанию): Xcode 27.1, раннер `xcode-27`;
- `release-13.0.0`: Xcode 26.6, раннер `macos-26`.

На раннере со старым Xcode сборка новой версии падает на API iOS 27
(`value of type 'UIView' has no member 'reservedRegions'`). Для нового тега нужен патч в
`patches/<тег>/`: если старый не накладывается, его переносят, как описано ниже.

## Установка на iPhone

`.ipa` подписан фейковым сертификатом, перед установкой его нужно переподписать:
- **AltStore / SideStore**: бесплатный Apple ID, подпись на 7 дней, потом приложение нужно обновить;
- **Sideloadly** (Windows/macOS): то же самое; можно сменить bundle id, чтобы AyuGram
  стоял рядом с официальным Telegram;
- **TrollStore**: только на поддерживаемых версиях iOS, без ограничения по сроку.

Для пуш-уведомлений подпись и профиль должны поддерживать APNs. Сам факт прихода пуша
ещё не означает, что расширение может расшифровать его содержимое.

Если при переподписи не выдана группа приложений `group.<bundle id>`, AyuGram хранит данные в
собственной папке приложения. Тогда не работают расширения: «Поделиться», виджеты и обработка
уведомлений.

### Пуш приходит без текста после подписи Feather

Telegram расшифровывает пуш в расширении `NotificationService`. Приложение и расширение
должны читать одну группу приложений. По умолчанию это `group.ph.telegra.Telegraph`,
а личный профиль подписи часто разрешает совсем другие группы.

1. В Feather откройте сертификат → Entitlements → `com.apple.security.application-groups`.
2. При запуске **Build AyuGram iOS** укажите одну полную разрешённую группу в поле
   `app_group_id`. Выберите группу, которую не использует другая сборка Telegram.
   Для повторных сборок можно сохранить её в переменной репозитория `AYUGRAM_APP_GROUP`.
3. Подпишите новый IPA в Feather тем же профилем, сохранив `NotificationService.appex`
   и App Groups профиля. Идентификатор приложения менять не требуется.
4. Установите обновление поверх приложения и один раз откройте его до проверки пушей.

Настройка меняет обращения к группе в приложении, обоих расширениях уведомлений,
«Поделиться», Siri, виджетах и трансляции экрана. Права фейковой подписи при сборке
сохраняются; реальные App Groups добавляет Feather при переподписи.

При первом запуске данные из прежней приватной папки копируются в новую общую папку,
включая ключ базы и метаданные аккаунтов. Исходная копия сохраняется. Уже существующая
общая база с аккаунтом не перезаписывается. Если расширение успело создать только пустую
служебную папку без каталога аккаунта, она сохраняется в `.ayugram-bootstrap-*` и заменяется
полной копией прежних данных. Неизвестное содержимое общей папки не заменяется.
Настройки скрытия текста при блокировке и предпросмотра уведомлений продолжают действовать.

Значение App Group записывается в `TelegramInfoPlist` основного приложения и в `AppNameInfoPlist`
расширений: приложение не включает второй фрагмент. После сборки workflow проверяет все
`Info.plist` внутри IPA и наличие `NotificationService`; несовпадение останавливает выдачу IPA.
Подробности проверки и сравнения со Swiftgram — в [docs/NOTIFICATION_FIX.md](docs/NOTIFICATION_FIX.md).

После переподписи клиент проверяет App Groups в фактических подписях приложения и
NotificationService. Если выбранная группа недоступна, используется доступная общая
группа из их прав. Если такой группы нет, нужно исправить профиль/параметры подписи
Feather: код не может предоставить отсутствующее право. Диагностика показывает обе подписи.

### Счётчики сохранённых удалённых сообщений

Сохранённое удалённое сообщение остаётся входящим, с прежним временем и позицией в истории.
Оно не увеличивает число непрочитанных, упоминаний или реакций. Удаление последнего сообщения
не опускает чат в списке. Остальные реальные непрочитанные сообщения не отмечаются прочитанными.
После обновления прежние сохранённые удаления получают новый признак; для затронутых чатов
счётчики проверяются по серверу без отправки новых отметок прочтения.

Переход из списка удалённых сообщений и повторная сверка истории с сервером сохраняют
локальную копию. Уже сохранённые сообщения остаются и после отключения сохранения новых
удалений; удалить их можно явным действием пользователя.

### Проверка текста и задержек push

Обычный зашифрованный push может содержать готовый текст. Расширение проверяет его ключом
из метаданных аккаунта до открытия полной базы и сохраняет как резервный вариант.
Если дальнейшая синхронизация задерживается, этот текст передаётся iOS через три секунды
после расшифровки. Служебные push прочтения и удаления получают тихий результат до ожидания
базы; обычное обновление счётчиков и удаление прочитанных уведомлений продолжается.
Для обычного текстового push расширение получает и сохраняет конкретное сообщение,
не ожидая полной синхронизации всех обновлений. Подтверждение доставки выполняется
параллельно; тайм-аут остаётся резервом при сбое. Диагностика показывает время обработки.
Звонки, истории и секретные чаты сохраняют прежний путь обработки.
Блокировка приложения продолжает скрывать текст.

При недоступной сети полная загрузка сообщений может завершиться только после открытия приложения.
Сохранение удалённых сообщений по-прежнему возможно, только если клиент успел получить их.

Пустая заглушка (пробел в заголовке, без звука) ставится только для push, которые намеренно
ничего не показывают: прочитано на другом устройстве, удалено, уже показано. Следующий push и
запуск приложения убирают такие заглушки. Если расширение не смогло расшифровать push (нет
аккаунта в общей папке, база или ключ недоступны), iOS показывает исходный общий текст push,
а не пустое уведомление.

Если вместо текста остаётся общий текст, откройте **Настройки → AyuGram → Дополнительно → Проверка уведомлений**
после нового push. Проверка показывает доступ к App Group, наличие расширения и последний этап:
поиск ключа, открытие базы, расшифровка, сеть или передача iOS. Также видно, хранит ли
приложение данные в приватной папке (и почему), сколько аккаунтов лежит в общей папке и сколько
аккаунтов с ключом push нашло расширение. Записываются только этап, время
и булевы признаки наличия текста и блокировки; сообщения, имена, токены и ключи не записываются.

## Изменение патча

```sh
git clone --depth 1 --branch release-13.1.1 https://github.com/TelegramMessenger/Telegram-iOS tg
cd tg && git apply ../patches/release-13.1.1/0001-ayugram.patch
# …правки…
../scripts/make-patch.sh .
```

Код AyuGram в патче:

| Файл | Что делает |
|---|---|
| `submodules/AyuGram/AyuGramSettings` | Настройки (UserDefaults) и список подавляемых TL-функций |
| `TelegramCore/Sources/AyuGram/AyuMessageAttributes.swift` | Атрибуты «удалено» и «история правок» |
| `TelegramCore/.../Network.swift` | Фильтр режима призрака на уровне запросов |
| `TelegramCore/.../ManagedAccountPresence.swift` | Статус «в сети» |
| `TelegramCore/.../AccountStateManagementUtils.swift` | Пометка вместо удаления, запись правок |
| `TelegramCore/.../SyncCore_StandaloneAccountTransaction.swift` | Сохранение атрибутов при обновлении сообщения |
| `SettingsUI/Sources/AyuGram/AyuGramSettingsController.swift` | Экран настроек |
| `ChatMessageBubbleItemNode`, `StringForMessageTimestampStatus` | Полупрозрачность и метка 🗑 |
| `ChatInterfaceStateContextMenus.swift` | Пункт «История правок» |

## Ограничения

- Настройки общие для всех аккаунтов (в AyuGram4A они задаются для каждого аккаунта отдельно).
- Медиа удалённых сообщений остаётся только если оно уже было в кэше.
- Удаление локальной базы или самого приложения стирает сохранённый архив. Сервер его не восстановит.
- Режим призрака не скрывает реакции, ответы и отправку сообщений: это видно собеседнику.
- Скрытие историй не убирает кольца историй вокруг аватарок в списке чатов.
- Не перенесены: отложенная отправка, regex-фильтры, shadow ban, локальный Premium.
- Из настроек AyuGram расширение уведомлений знает только «Сохранять удалённые»: приложение передаёт его через общую папку. Без общей App Group расширение сохраняет удалённые сообщения всегда.
