# Общая папка приложения и уведомлений

Проверка готового артефакта `AyuGram-iOS-105` выявила причину раздельного хранения данных:

| Bundle | `AyuGramAppGroup` в готовом `Info.plist` |
| --- | --- |
| Основное приложение | отсутствует, используется стандартная группа из bundle id |
| `NotificationService.appex` и остальные расширения | заданная `AYUGRAM_APP_GROUP` |

`configure-app-group.py` добавлял ключ только в `AppNameInfoPlist`. Все шесть расширений
включают этот фрагмент, а основное приложение включает `TelegramInfoPlist`. В результате
приложение могло работать с прежней приватной базой, пока расширение открывало пустую
общую папку и не находило аккаунт/ключ расшифровки.

Исправление добавляет ключ в оба фрагмента. `verify-app-groups.py` проверяет уже собранный
IPA перед публикацией артефакта: главный bundle, все `.appex` и наличие расширения уведомлений.
На исходном IPA 105 проверка воспроизводит несовпадение главного bundle. Unit-тест отдельно
покрывает эту конфигурацию, а также ошибочную группу расширения и отсутствие сервиса.

Расширение могло успеть создать `telegram-data` без аккаунтов. Импорт сохраняет такой bootstrap
в отдельную резервную папку и переносит туда прежнюю полную базу вместе с `.tempkey`.
Каталоги с аккаунтами или неизвестным содержимым не заменяются, приватный источник сохраняется.
Тесты переноса проверяют данные сообщений, ключ, WAL, резервную копию и сохранность общей базы.

## Сравнение со Swiftgram

Изучен публичный исходный код Swiftgram на коммите
[`e3a3922`](https://github.com/Swiftgram/Telegram-iOS/tree/e3a392272b182dbf975d4ac5fc33b40a5954d749):

- [SGAppGroupIdentifier.swift](https://github.com/Swiftgram/Telegram-iOS/blob/e3a392272b182dbf975d4ac5fc33b40a5954d749/Swiftgram/SGAppGroupIdentifier/Sources/SGAppGroupIdentifier.swift)
  вычисляет общую группу из базового bundle id приложения.
- [NotificationService.swift](https://github.com/Swiftgram/Telegram-iOS/blob/e3a392272b182dbf975d4ac5fc33b40a5954d749/Telegram/NotificationService/Sources/NotificationService.swift)
  открывает ту же группу, ищет ключ аккаунта, расшифровывает push и использует заголовок
  APS и данные отправителя. Разблокировка телефона сама по себе не устраняет ошибку
  доступа к общей базе. Механизм скрытия текста при блокировке приложения сохраняется.

В AyuGram этот же принцип применяется к явно выбранной разрешённой группе профиля Feather.
Права фейковой подписи при компиляции остаются совместимыми с фейковыми provisioning profiles;
реальные права профиля добавляются при переподписи. Проверка IPA проверяет конфигурацию
времени выполнения, а не выдачу прав Apple после переподписи.

## Реальные права после переподписи

На устройстве со сборкой 109 проверка показала: `group.9a4ace9772444b6ad.5`
из конфигурации недоступна через системный API. Совпадения Info.plist в IPA недостаточно:
права профиля сертификата и права установленного исполняемого файла могут различаться.

`AyuAppGroupResolver` читает App Groups из XML entitlements в Mach-O подписях самого
приложения и NotificationService. Приоритет имеет выбранная в сборке группа, если она
разрешена обоим. Затем проверяются стандартная группа и остальные общие группы в
стабильном порядке. Кандидат должен быть доступен текущему процессу через системный API.
Один механизм используется всеми десятью обращениями к App Group и диагностикой.
Перенос старой приватной базы выполняется до открытия аккаунта в найденной общей папке.

Это не выдаёт новых прав и не изменяет профиль. Если общей доступной группы нет,
нужна переподпись приложения и расширения подходящим профилем. Новая проверка показывает
группы в обеих фактических подписях и наличие расширения даже при недоступной папке.

В Feather проверьте выбранный сертификат/профиль, отключите пользовательский файл
Entitlements, если он задан, и используйте `Merge Entitlements` в параметрах подписи.
Сохраняйте расширение NotificationService. Профиль должен разрешать одну и ту же группу
основному приложению и расширению; сторонняя строка в GitHub Variables не создаёт это право.
После обновления откройте приложение для переноса данных перед проверкой новых push.

## Push после прочтения на другом устройстве

`READ_HISTORY` приходит и для каналов, и для групп/личных чатов. Это команда обновить
прочитанное и убрать старые уведомления. Исходный внешний APNs alert может содержать
общий текст нового сообщения. Раньше до открытия базы не было подготовлено тихого
результата для этой команды, а полностью пустой результат не защищал от восстановления
исходного текста системой.

Теперь тип определяется из аутентифицированного расшифрованного payload до открытия
базы аккаунта. Для известных служебных команд сразу сохраняется результат без текста.
Обычный обработчик продолжает обновлять прочитанное, счётчик и доставленные уведомления.
Если результат пустой, применяется приём Swiftgram `legacyNotificationsFix`: пробел в
заголовке, отдельный thread, отсутствие звука, passive interruption level и нулевая
relevance. Значение badge сохраняется. Эта же защита действует при подавлении уже
прочитанного сообщения в обычном пути обработки.

Тесты различают `READ_HISTORY` для трёх типов peer, другие служебные команды, настоящие
сообщения и звонки. На macOS проверяются готовые `UNMutableNotificationContent`: тихое
представление пустого результата, сохранность badge и обычных уведомлений.

## Серия сообщений и настройка задержки AyuGram Desktop

В [AyuGram Desktop, countTiming](https://github.com/AyuGram/AyuGramDesktop/blob/0f2a31bb420de98f331990432265b131b8d836b5/Telegram/SourceFiles/window/notifications_manager.cpp#L397)
`disableNotificationsDelay` заменяет серверные `notifyCloudDelay`/`notifyDefaultDelay`
на `minimalDelay`. Для обычного сообщения это 100 мс, для пересланного — 500 мс.
Настройка управляет локальным планировщиком Desktop, в том числе ожиданием при активности
другого устройства. Она не меняет доставку APNs на iPhone.

В iOS до этого резервный таймер завершал обработку через три секунды, пока расширение
ожидало полную синхронизацию и подтверждение доставки. Обычные текстовые push теперь
запрашивают конкретное сообщение через существующий загрузчик TelegramCore. Полученная
серверная копия сохраняется до показа, включая атрибуты и ссылки на медиа: это сохраняет
работу архива удалённых сообщений. Если получить сообщение не удалось, используется
прежняя полная синхронизация. Реакции, служебные push, звонки, истории, секретные чаты и
push с вложениями сохраняют прежний путь.

Запрос подтверждения доставки выполняется параллельно и не удерживает показ уже
сохранённого сообщения. Проверки прочитанного, удалённого и повторов сохраняются;
прочитанное/удалённое повторно проверяется после загрузки. Трёхсекундный резервный
тайм-аут остаётся защитой при проблеме базы/сети, без обязательного ожидания на быстром пути.
В проверке уведомлений показывается время от получения расширением до передачи iOS,
измеренное монотонными часами для конкретного запроса. Задержка до запуска расширения
и длительность анимации баннеров iOS в это время не входят.

## Пустые уведомления вместо текста

Приём Swiftgram `legacyNotificationsFix` (пробел в заголовке) в Swiftgram включается отдельной
настройкой и по умолчанию выключен. Здесь он применялся к любому пустому результату расширения,
в том числе к ошибкам: не найден аккаунт с ключом push, база не открылась, ключ недоступен,
расшифровка или разбор JSON не удались. Тогда каждое сообщение превращалось в пустое уведомление
«Telegram» без отправителя и текста — та же ошибка, что раньше выглядела как общий текст APNs.

Теперь результат ошибки помечается `ayuDeliverOriginal`, и iOS получает исходный push. Заглушка
остаётся только для намеренно пустых результатов (служебные push, прочитанные, удалённые и уже
показанные сообщения). Если резервный текст расшифрован, он показывается как раньше; для
служебного push сохраняется тихий результат. Заглушки из потока `ayu-service-notifications`
удаляются при следующем push и при запуске приложения.

Чаще всего ошибка — `keyNotFound`: расширение открыло общую папку, но аккаунта там нет, потому что
приложение работает с приватной папкой. Приложение теперь записывает причину (группа недоступна
или перенос не удался), а проверка показывает её, число `account-*` в общей папке и число записей
аккаунтов с ключом push, которое видело расширение.
